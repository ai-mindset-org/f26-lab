# шаблоны · что ещё можно показать из волта и системы агентов

Гайд к system board. Каждый шаблон отвечает на один вопрос о твоей системе. Источник – то, что у тебя уже лежит в папках, без новых сервисов. Шаблоны собраны из живой системы автора лабы: там они работают каждый день, здесь описаны без его данных.

Как читать карточку: **вопрос** – что хочешь знать каждый день · **источник** – откуда сборщик берёт данные · **форма** – как рисовать · **ловушка** – где цифра врёт.

## день

### 1. таймлайн дня ● на доске
- **вопрос:** где ушёл день
- **источник:** транскрипты сессий (`~/.claude/projects/*/*.jsonl`, `~/.codex/sessions/ГГГГ/ММ/ДД/`), время файлов волта, экспорт чатов, `git log`
- **форма:** дорожки на одной оси времени: строка – сессия, полоса – отрезок без паузы дольше 20 минут; события – точки и штрихи
- **ловушка:** сессия, открытая утром и продолженная вечером, – это два отрезка, а не один день работы. Режь по паузам

### 2. ритм: человек и агенты ● на доске
- **вопрос:** сколько пишешь ты и сколько делают агенты
- **источник:** в транскриптах строки `user` без `tool_result` – твои просьбы, `tool_use` – действия агента
- **форма:** два ряда столбиков по часам, у каждого своя шкала
- **ловушка:** одна ось на обе величины. Просьб десятки, действий сотни: первый ряд превращается в ноль

### 3. сессия → результат ○ следующий
- **вопрос:** какие сессии закончились файлом, а какие ничем
- **источник:** отрезки сессий из шаблона 1 + новые файлы за то же время в той же папке
- **форма:** точка на сессию: заполненная – есть файл, пустая – нет
- **ловушка:** файл из автоматики (бэкап, синхронизация) засчитывается как результат. Отфильтруй по типу в имени

## контекст

### 4. бюджет контекста ● на доске
- **вопрос:** сколько окна съедено до первого слова
- **источник:** файлы, которые агент читает всегда (`CLAUDE.md`, `AGENTS.md`, индекс памяти), плюс описания всех skills
- **форма:** одна полоса от нуля до окна, сегмент на источник, отметки 60% и 80%
- **ловушка:** токены считаются оценкой по символам. Подпиши знаком ≈ и формулой

### 5. правила по весу ● на доске
- **вопрос:** какие разделы правил самые тяжёлые
- **источник:** заголовки `##` главного файла правил
- **форма:** список с полоской веса, CRITICAL отмечены цветом
- **ловушка:** длинный раздел не обязательно плохой. Вопрос к нему: это «всегда» или процедура для одной работы, которой место в skill

### 6. дрейф правил ○ следующий
- **вопрос:** что поменялось в правилах за неделю
- **источник:** `git log --stat` по файлам правил и папке `rules/`
- **форма:** столбик на день, сколько строк добавлено и убрано
- **ловушка:** правило, которое растёт каждый день, – сигнал вынести его в skill

### 7. память агента по типам ○ следующий
- **вопрос:** что агент о тебе помнит: факты о тебе, поправки, проекты, ссылки
- **источник:** папка памяти: тип в шапке каждого файла
- **форма:** четыре числа и лента последних поправок
- **ловушка:** память без даты устаревает. Показывай возраст

## skills

### 8. размер skills ● на доске
- **вопрос:** какие skills простые, какие стали программами
- **источник:** строки во всех файлах папки skill
- **форма:** точка на skill по логарифмической шкале, подписаны 3–4 ориентира
- **ловушка:** линейная шкала. Skill на 7 строк и на 6000 в одной линейке не видны оба

### 9. обновления skills ● на доске
- **вопрос:** что ты чинишь чаще всего
- **источник:** время изменения файлов в папке skill или `git log`; точнее – хук после записи, который пишет строку в журнал правок
- **форма:** столбик на день за две недели, цвет по папке
- **ловушка:** массовая синхронизация зеркал помечает все skills одним днём. Считай по источнику, а не по зеркалу

### 10. журнал запусков ○ следующий
- **вопрос:** какой skill падает и на чём
- **источник:** `runs.md` или `logs/{log} skill runs.md`: строка на запуск, PASS или FAIL
- **форма:** штрих на запуск, FAIL цветом, наведение – что поправить
- **ловушка:** запуск в том же чате, где skill писали, ничего не доказывает. В журнал – только чистые чаты

## знания

### 11. поток заметок по типам ○ следующий
- **вопрос:** что ты производишь: планы, разборы, черновики, расшифровки
- **источник:** теги типа в именах файлов: `{plan}`, `{meeting}`, `{draft}`
- **форма:** стопка на неделю, слой на тип
- **ловушка:** файлы без типа. Если их больше трети, сначала правило имён, потом дашборд

### 12. граф ссылок ○ следующий
- **вопрос:** какие заметки держат систему
- **источник:** `[[ссылки]]` между файлами волта
- **форма:** узлы по числу входящих ссылок, только верхние 30
- **ловушка:** весь граф целиком – клубок. Показывай верх и соседей одной заметки

### 13. обещания после звонков ○ следующий
- **вопрос:** кто кому что должен и к какому сроку
- **источник:** результат skill `call-digest` по заметкам встреч: «обязательства» и «уточнить»
- **форма:** список по сроку, просроченное цветом
- **ловушка:** обещание без срока теряется. Оно идёт в «уточнить», а не в список

## рутины

### 14. рутины по расписанию ○ следующий
- **вопрос:** что работает без тебя и когда
- **источник:** cron, launchd, автоматизации Codex, задачи по расписанию в чате
- **форма:** дорожка на рутину по часам суток, последний запуск и его итог
- **ловушка:** одна задача в двух планировщиках. У каждой рутины ровно один хозяин

### 15. журнал волта ○ следующий
- **вопрос:** что агенты сделали с волтом за неделю
- **источник:** файл-журнал, куда агент дописывает строку на операцию: `## [ГГГГ-ММ-ДД] операция | название`
- **форма:** лента по дням, цвет по операции
- **ловушка:** журнал, который пишут руками, перестаёт вестись через неделю. Пусть пишет агент

## как выбрать следующий

1. возьми вопрос, который задаёшь себе каждый день или каждую неделю
2. найди, где ответ уже лежит в папках: транскрипт, имя файла, журнал, git
3. добавь в `collect.py` одну функцию, которая только читает, и одно поле в json
4. нарисуй одну фигуру с номером и вопросом в шапке
5. запусти `check.mjs`, посмотри снимок, допиши строку в `runs.md`

Шаблоны 1–15 выросли из одной системы. Твой вопрос важнее этого списка.
