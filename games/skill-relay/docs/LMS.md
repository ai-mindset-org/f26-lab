# эстафета skills в LMS

Игра живёт на своём адресе и показывает один стол на двух поверхностях: веб-версия с единым входом и версия в теме LMS. Журнал один. Изменение, внесённое из LMS, сразу видно в вебе, и наоборот.

## что встраивается

| что | адрес | вход |
|---|---|---|
| карточка на страницу лабы | `<адрес игры>/card` | без входа, имён участников нет |
| стол в теме LMS | `<адрес игры>/?skin=lms` | сессия игры |
| вход из LMS | `POST <адрес игры>/api/mint` с сервера LMS | общий секрет |

Тема выбирается параметром `?skin=lms` или `?skin=web` и запоминается в браузере. Переключатель «веб · LMS» стоит в меню игры.

## карточка

Карточка повторяет устройство карточки «компас»: значок, название, строка состояния, список skills с дорожкой версий, подвал со ссылкой «взять skill →». Обновляется сама раз в десять секунд.

```html
<iframe src="<адрес игры>/card" width="460" height="430" style="border:0" title="эстафета skills"></iframe>
```

- тёмная тема: `<адрес игры>/card?theme=dark`
- сервер игры разрешает встраивать карточку только сайту из переменной `RELAY_FRAME_ANCESTORS` (например, адрес LMS). Остальные страницы игры во фрейм не встают.
- ссылка в подвале ведёт на адрес из `RELAY_LMS_LINK`. Если переменная пуста, ссылка открывает стол в теме LMS, и человек входит единым входом.

## вход из LMS

LMS уже знает участника. Серверная функция LMS просит у игры одноразовую ссылку и отправляет человека по ней.

```js
// выполняется на сервере LMS: секрет в браузер не попадает
const r = await fetch(RELAY_URL + '/api/mint', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-Mint-Secret': process.env.RELAY_MINT_SECRET },
  body: JSON.stringify({ tg_id, username, display_name, source: 'lms' }),
});
const d = await r.json();
if (d.authorized) return Response.redirect(d.auth_link, 302);
// d.reason === 'not_on_roster': человека нет в составе стола
```

Ответ игры: `{"authorized": true, "auth_link": "<адрес игры>/auth/complete?token=…", "ttl": 900, "surface": "lms"}`.

- ссылка живёт 15 минут и срабатывает один раз
- после перехода игра ставит свою cookie сессии и открывает стол в теме LMS
- поле `source: "lms"` подписано внутри ссылки: в журнале стола вход записан как «вход: LMS», у каждой версии этого человека видно имя и способ входа
- `tg_id` обязателен (цифры), `username` и `display_name` берутся из профиля LMS

Адрес функции LMS, которая делает этот запрос и редирект, кладётся в `RELAY_LMS_LINK` на сервере игры: туда ведут карточка и кнопка входа.

## состав

Входит тот, кто есть в `roster.json` стола: `tg_id`, `login`, `name`. Состав собирается из среза участников лабы. Запуск с флагом `--open` дописывает новых людей при первом входе.

## переменные сервера игры

| переменная | зачем |
|---|---|
| `RELAY_MINT_SECRET` | общий секрет с LMS для `/api/mint` |
| `RELAY_SESSION_SECRET` | подпись сессий и одноразовых ссылок |
| `RELAY_LMS_LINK` | адрес входа в LMS для карточки и кнопки входа |
| `RELAY_FRAME_ANCESTORS` | какому сайту можно встроить карточку |
| `RELAY_PUBLIC_URL` | внешний адрес игры в ссылках |

## что решить перед включением

1. Где стоит карточка: страница лабы рядом с компасом или отдельный раздел.
2. Кто заводит серверную функцию входа в LMS и где хранит секрет.
3. Нужен ли единый вход на веб-версии одновременно со входом из LMS. Технически они работают рядом и приводят одного человека к одной записи состава по `tg_id`.
