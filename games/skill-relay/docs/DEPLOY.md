# размещение эстафеты

Сервер эстафеты один процесс на стандартной библиотеке Python. Состояние лежит в папке стола. Перед сервером нужен https-прокси.

## что нужно на сервере

| что | зачем |
|---|---|
| папка стола | `python3 relay.py init <стол>`; резервная копия = копия папки |
| `RELAY_SESSION_SECRET` | 32 байта в hex; подписывает билеты входа и сессии |
| `RELAY_MINT_SECRET` | общий секрет с ботом; без него адрес выдачи ссылок закрыт |
| `RELAY_PUBLIC_URL` | внешний адрес с `https://`; включает `Secure` и префикс `__Host-` у cookie |
| `RELAY_BOT_LINK` | ссылка на бота для кнопки «войти через Telegram» |
| `OPENROUTER_API_KEY` | разбор моделью; без ключа работают признаки |
| `RELAY_REVIEW_MODEL`, `RELAY_REVIEW_CAP` | модель разбора и дневной потолок вызовов |

Запуск: `python3 relay.py serve <стол> --live --port 8996`. Сервер слушает `127.0.0.1`, прокси передаёт ему запросы с исходным заголовком `Host`. Секреты живут в окружении службы и в папку стола не пишутся.

## вход через бота

Схема та же, что у остальных сервисов с входом по ссылке: бот знает человека по Telegram, сервис получает одноразовый билет.

1. Человек пишет боту команду или жмёт кнопку.
2. Бот шлёт `POST /api/mint` с заголовком `X-Mint-Secret` и телом `{"tg_id": "...", "username": "...", "display_name": "..."}`. Принимается и исходное обновление Telegram: `{"telegram": {...}}`.
3. Сервер сверяет `tg_id` с составом и отвечает `{"authorized": true, "auth_link": "<адрес>/auth/complete?token=...", "ttl": 900}`. Человека нет в составе: `{"authorized": false, "reason": "not_on_roster"}`.
4. Бот присылает человеку кнопку со ссылкой. Ссылка живёт 15 минут и срабатывает один раз.
5. `GET /auth/complete` ставит сессию на 30 дней и ведёт на страницу.

Остальные адреса: `GET /api/auth/me`, `POST /api/auth/logout`. Билет входа и сессия подписаны HS256 одним секретом и различаются полем `aud`: `relay-login` и `relay`.

Пока ветки в боте нет, ссылки выдаёт ведущий командой `relay.py mint` и шлёт каждому лично.

Флаг `--open` пускает любого, кого прислал бот, и дописывает его в состав. Без флага входят только люди из `roster.json`.

## состав и анкеты

`roster.json` в папке стола:

```json
{"people": [{"login": "nik", "tg_id": "123456789", "name": "Имя", "profile": {"harness": "Claude Code", "level": "уверенный", "focus": "исследования"}}]}
```

Сервер читает файл при каждом запросе, поэтому состав обновляется без перезапуска. Человек, которого убрали из состава, теряет доступ на следующем запросе. Поля `profile` показываются в шапке участника; `harness` и `level` берутся из анкеты лабы. Скрипт выгрузки из базы участников пишет этот файл по расписанию или перед игрой.

## превью и рабочий адрес

Превью для ведущего поднимается на его машине во внутренней сети и не требует выпуска ветки:

```
rsync -az --delete --exclude __pycache__ games/skill-relay/ <машина>:apps/skill-relay/
python3 relay.py init ~/.local/var/skill-relay/table --demo
python3 relay.py serve ~/.local/var/skill-relay/table --demo --bots 8 --port 8996 --public-url https://<машина>.<сеть>.ts.net:<порт>
tailscale serve --bg --https=<порт> http://127.0.0.1:8996
```

Сервер запускается user-юнитом systemd, ключ модели и `RELAY_REVIEW_CAP` лежат в файле окружения с правами 600. Адрес виден только участникам сети Tailscale.

Рабочий адрес для участников: отдельный пользователь и юнит на сервере приложений, сервер слушает `127.0.0.1`, перед ним Caddy с сертификатом, запись в реестре автоматизаций. Ключ модели для рабочего адреса отдельный, с дневным потолком на стороне OpenRouter. Демо-места на рабочем адресе выключены: режим `--live`.

## место в LMS

В LMS ставится карточка-ссылка на адрес эстафеты и вторая ссылка на книгу правил `guides/RULES.md`. Встраивание рамкой отключено: политика содержимого запрещает рамки, а cookie с `SameSite=Lax` в чужой рамке не передаётся.

Вход из LMS без бота: серверная функция LMS вызывает `POST /api/mint` с тем же секретом и перенаправляет человека по `auth_link`. Участник нажимает карточку на странице лабы и попадает на стадион уже вошедшим; ветка в боте для этого пути не нужна. В журнале стола такой вход записан как «одноразовая ссылка».

Харнесса участника в анкете лабы нет. Его можно спросить один раз при первом входе или передать полем `profile.harness` при выдаче ссылки.

## сколько стоит разбор

Один забег делает до четырёх вызовов модели: выбор правил при взятии и до трёх разборов. На `anthropic/claude-sonnet-5.5` замер 16.11.2026 дал $0,02–0,03 за вызов. Игра на 30 человек по два забега укладывается в $5. Потолок `RELAY_REVIEW_CAP` останавливает вызовы и переводит разбор на признаки.

## перед запуском на группу

- `python3 docs/check.py` проходит целиком, `python3 docs/check.py --model` показывает настоящий разбор.
- Вход проверен на двух людях: один из состава, один чужой.
- Часы: `--hour` и `--lock` в секундах, по умолчанию 3600 и 1200. На встрече в 60 минут ставь `--hour 1200 --lock 600`, иначе каждый успеет один забег.
- Число дорожек: до 15 человек хватает пяти, дальше `init --heats 2`.
- Ведущий держит открытым `python3 relay.py state <стол>` и файл `TRAIL.md`.
