# skills · сводный гайд для участников F26

Гайд собран из исследования по восьми источникам и из харнеса лабы. Каждый раздел привязан к сущности онтологии слоя 2: **рутина, вход, skill, правило, запуск, проверка, журнал, маршрут**. Харнес вживую: [слой 2](https://f26-harness.lab.aimindset.org/app.html?layer=2) · [онтология](https://f26-harness.lab.aimindset.org/app.html?layer=2&tab=onto) · [гид](https://f26-harness.lab.aimindset.org/guide.html).

## 1. рутина · какую работу брать

Лестница повторения: **шорткат** повторяет движение, **шаблон** повторяет текст, **skill** повторяет работу по описанию и зовётся словами, **рутина** запускает тот же skill по расписанию (неделя 3), **агент сам** запускает по событию и требует проверки на каждом запуске.

Часы за год на одну рутину:

| как часто | 1 минута | 10 минут | 1 час |
|---|---|---|---|
| 5 раз в день | 30 ч · шорткат | 304 ч · skill первым | 1825 ч · skill + расписание |
| каждый день | 6 ч · шорткат | 61 ч · skill словами | 365 ч · skill + журнал |
| раз в неделю | 1 ч · руками | 9 ч · skill словами | 52 ч · skill + проверка |
| раз в месяц | 12 мин · руками | 2 ч · чек-лист | 12 ч · skill, если вход понятен |

**Фильтр:** раз в неделю и чаще · вход понятен · проверить результат быстрее, чем сделать. Лучший первый кандидат – работа, которую уже раз сделал с агентом в чате: попроси записать удачный путь в skill.

## 2. вход · с чего начинается запуск

Вход – файл или фрагмент, с которым работает skill: заметка созвона, письмо, выгрузка задач. Учебный вход W2 – четыре строки созвона: Аня со сроком, Борис со сроком, Вера без срока, обсуждение без решения. Для проверки нужен ещё **вход, где skill не должен сработать**: заметка без обещаний.

## 3. skill · анатомия

Папка `skills/<имя>/SKILL.md`. Шапка видна агенту всегда, тело открывается по условию, справочные файлы – по запросу.

```
---
name: call-digest
description: обещания после звонка. бери, когда есть заметка или расшифровка
---
вход:     заметка созвона
шаги:     найди обещания; у каждого кто и срок; чего-то нет – в «уточнить»
выход:    «обязательства» и «уточнить»
проверка: у каждой строки номер из входа
эталон:   examples/хороший-разбор.md
```

- **description** = что делает + когда брать, словами твоей просьбы. Модель склонна не брать skill сама, поэтому описание пишут настойчиво, а по имени звать надёжнее
- **цель и «готово»** до шагов · одно действие на шаг · каждое «смотря как» переписать в «если – то»
- **эталон** готового результата рядом: по примеру модель калибруется точнее, чем по описанию
- размер свободный: grill-me – 7 строк, daily-focus – 4277 строк в 10 файлах и хаб. Начинать с короткого

**Три промпта, чтобы написать skill в любом чате:** рассказать, как делаешь сейчас, и попросить три вопроса · нарисовать схемой mermaid: вход, шаги, где решаешь ты, выход · превратить в SKILL.md короче 40 строк с твоими «всегда» и «никогда».

## 4. правило · что читается всегда

`AGENTS.md` / `CLAUDE.md` и `rules/` держат «всегда» (до 200 строк). Процедура для одной работы уезжает в skill, в правилах остаётся строка «когда → skill». Сигнал к переносу: одну и ту же инструкцию вставляешь в чат второй раз.

Хаб – skill, который зовёт другие: план дня сам зовёт задачи и календарь. Зеркало – один источник в двух папках: `.claude/skills` читает Claude, `.agents/skills` читают Codex и ChatGPT.

**Доступ** – поле `access` в файле, уровни из онтологии харнеса:

| уровень | что | агент |
|---|---|---|
| T0 публичное | уже открыто миру | читает и цитирует |
| T1 рабочее | self, проекты, решения | читает на старте |
| T2 адресное | выбранное для человека | показывает только адресату |
| T3 личное | `private: true` | только по просьбе в этой сессии |
| T4 уязвимое | здоровье, данные других | в папку не кладётся |

Исходящее агент кладёт черновиком в `drafts/`, отправляет человек.

## 5. запуск · как позвать

- Claude Code: `/call-digest meetings/созвон-12.11.md`
- Codex: `$call-digest` на заметке или `/skills` и выбрать
- ChatGPT: `@call-digest` · любой чат: «вот SKILL.md, выполни по нему на этом входе»
- дописать к просьбе: сверь с эталоном · у каждой строки номер из входа · назови файлы, которые прочитал

Каждый тестовый запуск – в новом чистом чате. Тест в чате, где skill писали, ничего не доказывает.

## 6. проверка · кто принимает результат

- **тот же вход дважды** – результат тот же
- **вход, где skill не должен сработать** – пустой результат
- **проверяющий агент** получает только вход, результат и признак: «назови строки результата без основания во входе: номер и выдержку». В Claude Code это сабагент, в любом сервисе – новый чистый чат
- оценка «да / нет» по каждому пункту и PASS только с цитатой из результата
- прежде чем писать проверки, прочитай реальные результаты и выпиши первую ошибку в каждом

## 7. журнал · строка на запуск

`logs/{log} skill runs.md`: дата · skill · вход · что вышло · что поправить. Три строки журнала показывают, какую строку skill менять. Карточка проверки лежит в `evals/{eval} <skill>.md`.

## 8. маршрут · где запускается

Три входа в один skill: **чат** – текст skill в начале сообщения · **файл** – SKILL.md приложен к запросу · **папка** – агент находит skill сам. Модель любая: Claude, ChatGPT, Codex, Gemini читают один и тот же файл.

Чужой skill до запуска читается по трём вопросам: когда срабатывает · что читает · что пишет или запускает. Образцы: [github.com/anthropics/skills](https://github.com/anthropics/skills) · [skills.sh](https://skills.sh).
